## Failed result recovery

Raw and decoded reports are retained outside Git under the owner-only directory:

`/Users/robert/Library/Application Support/whitehouse-security/`

Each archive has a manifest; raw log checksums are SHA-256. Files are mode 0600 and archive directories 0700. Reports can contain secret findings, so do not attach them to PRs or print them.

`security/tools/archive_completed_scans.py` makes recovery repeatable. It uses only standard Python libraries and kubectl, archives completed vulnerability-scan jobs without mutating the cluster, decodes the operator's base64/bzip2 output, and emits only archive location/counts. Failures return a nonzero exit and are recorded without printing raw error/log content. Valid reports can omit Results entirely. Archive names include pod and container names, and receipts retain job UIDs.

Example:

```sh
python3 security/tools/archive_completed_scans.py \
  --directory "$HOME/Library/Application Support/whitehouse-security"
```

Recovered oversized results include unified-sdr (12 critical, 379 high, 3,900 medium package findings) and CompreFace (127 critical, 1,647 high, 3,721 medium; 4,402 unique vulnerability IDs). These are scanner outputs under the existing filters, not exploitability determinations. CompreFace warrants explicit exposure and supported-upgrade review.

This is a manual recovery tool, not continuous storage. Automated full-report retention, summary/coverage export, and staleness alerting remain to implement; existing CRD-backed reporting remains in use.
