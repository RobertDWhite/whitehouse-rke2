# Cluster security review — 2026-10-23

## Confirmed findings

- Trivy had only two VulnerabilityReports across 457 running pods. Five completed scan jobs occupied all scan slots: three produced oversized reports rejected by etcd/API limits, and two had unavailable container logs that appeared as base64 parsing errors. A one-hour completed-job TTL is configured and the five stuck jobs were given the same TTL. Scans resumed. This prevents indefinite queue blockage; it does **not** solve storage of oversized reports or prove complete coverage. Existing scan settings omit unfixed vulnerabilities and low severity findings.
- The four existing Kyverno policies were Audit/Ignore. An invalid Helm hook label selector prevented policy updates. That selector is removed. A separate enforced, fail-closed policy now rejects privileged containers, host namespaces and hostPath in the FreshRSS, Wallabag, Monica and MISP namespaces. Existing FreshRSS/MISP/Wallabag controller templates passed admission dry runs. Other namespaces remain audit-only.
- CrowdSec had no active remediation bouncer registered (only old dashboard consumers). Its configured acquisition covers NGINX, not the Envoy gateway now handling many routes. Detection and blocking need an Envoy integration plus end-to-end tests. A running CrowdSec pod is not evidence that requests are blocked.
- Falco runs on amd64 nodes only; the ARM64 node is outside its current coverage. One other node was NotReady. Runtime coverage needs remediation and alerting.
- Many application namespaces lack NetworkPolicies, and several policies permit all egress. Internal DNS names on a shared gateway are not access controls. Private-address restrictions were applied to both public and internal PHP routes as exposure reduction. Upstream proxy/NAT source preservation and denial from an independent WAN client are not yet verified; these restrictions do not replace patching or protect against compromised private-network clients.

## eMudhra trust-store incident

Sampled system CA bundles in FreshRSS, MISP, brain-mcp, graph embeddings, Pages, Meerkat MCP and Argo CD included emSign ECC Root CA - G3 before upgrades. This is an outbound client trust risk even when inbound website certificates use Let's Encrypt. The sample is not a full inventory of OS, Python certifi, Java, Node or embedded Go trust stores. Rebuild/redeploy affected images with updated CA bundles and verify every effective trust store; do not disable certificate verification. Node trust stores also require assessment. No compromise or absence of compromise has been established by this review.

## Deployment and next steps

Upgrade manifests and containment controls were developed on `codex/cluster-security-20261023` and integrated with the latest `main` for deployment. Application source revisions remain on `main`: the app-of-apps controller resets temporary branch overrides. The pinned MISP core image also needs a narrow startup workaround to restore the missing executable bit on `/init_misp.sh`; the upstream file-mode fix is [MISP/misp-docker#479](https://github.com/MISP/misp-docker/pull/479).

Priorities remaining: patched Wallabag image and compatibility test; exhaustive trust-store remediation; Envoy CrowdSec/AppSec blocking with client-IP validation; scan coverage/staleness/queue alerts and durable storage for oversized reports; tighter network egress and admission controls with workload-specific exceptions; ARM64 runtime detection; review high/critical scan findings against current running images. This is a targeted review and containment pass, not a declaration that the cluster is secure.

## General posture follow-up — 19:35 UTC

A repeatable read-only inventory is available in `security/tools/posture_snapshot.py`; its selected-metadata output is `security/posture-2026-10-23.json`. It never fetches Kubernetes Secret objects or emits pod environment variables. The snapshot observed 454 running pods, 257 distinct running main-container digests, and 182 vulnerability reports. Only 61 running digests matched reports (23.7%); 28 matched images contained critical findings. Digest matching is a lower bound because index and platform digests can differ. Init/ephemeral containers are not in this denominator. Repeated ReplicaSet and CronJob reports are deduplicated by digest. Scanner severity is not proof that the vulnerable code is reachable or exploited.

### Changes applied and tested

- Wallabag now has pod-level ingress and egress isolation. Only the Envoy proxy pods and uptime monitoring namespace may reach port 80. DNS to CoreDNS and public IPv4 HTTP(S) fetching are allowed; private, link-local, loopback and tailnet destinations are excluded, with IPv6 denied. This intentionally prevents saving private-network articles. Tests confirmed public HTTPS connectivity, denied cluster API/metadata connections, denied ingress from a disposable unrelated default-namespace pod, and HTTP 302 through the TLS gateway. Local DNS did not resolve the internal hostname; gateway testing used its verified load-balancer IP with the original hostname/SNI. This is containment, not a PHP patch. Public HTTP(S) remains a possible exfiltration path. Same-node host traffic is not comprehensively isolated by Kubernetes NetworkPolicy.
- Falco's existing pinned images were verified to publish ARM64 manifests. Scheduling now includes ARM64. The node-10 sensor became Ready and opened the modern BPF syscall source. A disposable terminal-shell test generated the expected `Terminal shell in container` Notice event on node-10 at 19:38:01 UTC. This verifies capture; delivery to Matrix was not tested (the existing webhook minimum is Error). Temporary test pods were removed. The offline node-12 remains outside active coverage.
- Added Prometheus alerts for unavailable Trivy metrics, completed scan jobs retained after ingestion should finish, and Ready nodes lacking a Ready Falco sensor. Promtool validated all 37 rules in the updated file; Prometheus loaded all three new rules with health `ok`. This does not yet alert on exact digest coverage or report staleness.
- Removed obsolete Paperless route and network policy referencing a nonexistent namespace and absent application. The gateway sync operation then reported all tasks run successfully. Other route drift/shared ownership remains; do not infer all routes are synchronized. MISP backend certificate verification remains enabled.

### Prioritized residual risks

1. **Incomplete detection and absent verified perimeter blocking:** Trivy coverage remains incomplete; CrowdSec's Envoy acquisition and remediation bouncer are still missing. Complete an Envoy-compatible integration and prove source-IP preservation and allow/deny behavior before relying on it. Existing private-source gateway restrictions are not an independently verified WAN test.
2. **Security/control-plane images require patching:** CrowdSec v1.6.4 has 22 critical and 509 high package findings. Its critical findings include libcrypto/libssl and bundled Go dependencies; the same CVE repeats across binaries. Upgrade with a database/config backup and verify decisions/parsers afterward. Argo CD v3.2.3 has 7 critical and 148 high findings. Control-plane privileges make these priorities even where services are internal. Longhorn engine/manager images also have critical findings; storage upgrades need version-compatible sequencing and restore validation, not a blind mass image replacement.
3. **Oversized findings remain unstored:** a stalled `unified-sdr` scan of `librespace/gnuradio:3.10.5.1` decoded to 4,291 package findings (12 critical, 379 high, 3,900 medium; 890 unique vulnerability IDs), and the controller rejected its roughly 2.17 MB report against a 2 MiB limit. Do not describe this as only an SBOM issue. Inspected operator 0.28.0 source shows alternate storage routes all vulnerability results to files instead of CRDs; turning it on blindly would remove CRD-backed reporting/metrics. Keep the current reporting path while designing durable detailed-report storage plus compatible summary/coverage export. One-hour job TTL and the new alert mitigate queue stalls but do not recover these missing findings. Existing `ignoreUnfixed: true` also hides unresolved exposures.
4. **Lateral movement and powerful identities:** 33 namespaces with running workloads had no NetworkPolicy after Wallabag isolation. Several others have allow-all egress; mere policy presence is not isolation. Hermes' `hermes-mcp` cluster-admin binding is explicitly intentional in its manifest and was preserved. Its application/agent inputs and reachable webhook therefore form a high-impact cluster-admin trust boundary. Portainer and Velero also hold cluster-admin. The snapshot lists exact bindings only, not all equivalent wildcard roles or escalation paths.
5. **Direct network exposure:** LoadBalancer/NodePort services include Ollama (11434), Loki (3100), InfluxDB (8086), Hermes webhook (8645), home-screen UI, and infrastructure endpoints. These can bypass gateway authentication and rate controls. This inventory establishes service exposure type, not Internet reachability; firewall/NAT validation and per-service authentication tests remain required.
6. **Unpatched applications and trust stores:** Wallabag's published runtime remains unpatched; upstream PR #484 is open. Congress app v0.1.1, legacy radio images, and several supporting services have critical findings and need controlled rebuilds/upgrades. Broad eMudhra trust-store remediation, node hardening, effective RBAC escalation review, backup restore testing, and investigation of any historical suspicious activity remain outstanding.
